````markdown
# VOLE MASTER IMPLEMENTATION BRIEF

## Native-Rust Procedural Video Storage, Transport, Inverse Proceduralization, and Deterministic Materialization Engine

You are implementing **VOLE — Video Object Layer Engine**.

VOLE is NOT primarily a conventional video codec.

VOLE is a **procedural video storage and transport architecture** in which raster frames are not assumed to be the fundamental persistent representation of video.

The central architectural idea is:

\[
G_{t+1}=\Phi(U,G_t,\Delta_t)
\]

\[
\hat F_t=M(U,G_t,V)
\]

\[
F_t=\hat F_t\oplus_{\rho}R_t
\]

where:

- `U` is a versioned deterministic universe of normative algorithms, tables, arithmetic, generators, transforms, and limits;
- `G_t` is the bounded **Procedural State Graph** at time `t`;
- `Φ` is a deterministic bounded state-transition operator;
- `Δ_t` is a compact transition description;
- `M` is the deterministic materializer;
- `V` is the requested view: frame, plane, tile, rectangle, scale, or other bounded materialization target;
- `R_t` is the residual information the procedural state does not reproduce;
- `⊕ρ` is an explicitly specified residual algebra.

The persistent video is therefore:

```text
procedural state
+ state evolution
+ immutable reusable objects
+ irreducible residual information
````

rather than fundamentally:

```text
compressed raster frame
+ compressed raster frame
+ compressed raster frame
+ ...
```

Raster samples remain an output representation because displays, image APIs, and conventional media pipelines require them.

They are not required to remain VOLE's primary storage ontology.

The core principle is:

> **Store the deterministic explanation. Encode what the explanation cannot reproduce. Materialize raster samples only when needed.**

This is not a claim that arbitrary video can be reduced to a small equation.

Information theory remains binding.

If a procedural explanation is poor:

$$
|R|\rightarrow|F|
$$

and VOLE must gracefully fall back toward ordinary literal, entropy-coded, motion-compensated, or transform-coded representation.

The architecture must never hide this.


```text

        ↓
VOLE state
        ↓
VOLE transitions
        ↓
```

Do not unnecessarily rasterize such content and then try to recover the structure.

The API must eventually permit applications to emit VOLE procedural state directly.

## 3.2 Raster-origin input

Camera footage, legacy codecs, screen capture, and arbitrary raster streams must use **inverse proceduralization**.

Conceptually:

```text
target raster observation
        ↓
candidate procedural explanations
        ↓
materialize candidate
        ↓
compute exact residual
        ↓
complete cost court
        ↓
best procedural state + residual
```

This process asks:

> Which bounded deterministic explanation reproduces the greatest amount of the target for the lowest complete representation cost?

This is one of VOLE's central research mechanisms.

# 4. CORE LOSSLESS OBJECTIVE

For an admissible hypothesis `H`:

$$
\hat F_H=M(H)
$$

and residual:

$$
R_H=F\ominus_{\rho_H}\hat F_H.
$$

The conceptual storage objective is:

$$
H^*
=
\arg\min_H
\left[
L(H)+L(F\mid H)
\right].
$$

For implementation, use actual accounted persisted bytes initially:

$$
J(H)=
B_{\mathrm{state}}
+
B_{\mathrm{transition}}
+
B_{\mathrm{objects}}
+
B_{\mathrm{residual}}
+
B_{\mathrm{models}}
+
B_{\mathrm{dictionary}}
+
B_{\mathrm{index}}
+
B_{\mathrm{integrity}}.
$$

Later profiles may add:

$$
J(H)=
B
+\lambda_eE
+\lambda_dD
+\lambda_mM
+\lambda_iI
+\lambda_hH_d.
$$

Where:

* `B` = complete persisted/transmitted bytes;
* `E` = encode work;
* `D` = materialization work;
* `M` = memory;
* `I` = dependency/object-fetch cost;
* `H_d` = dependency depth.

Do not compare only residual bytes.

Do not compare only descriptor bytes.

Count everything.

# 8. THE PROCEDURAL STATE GRAPH

Create the **Procedural State Graph** as a first-class normative data model from Phase A.

A conceptual state:

$$
G_t=(O,I,T,D,C,R,M)
$$

where:

```text
O = immutable object set
I = object instances
T = transforms / trajectories / motion state
D = generator / dynamics state
C = composition relationships
R = residual bindings
M = models / palettes / dictionaries / metadata
```

The implementation need not literally expose this tuple.

But the architecture must support these concepts without forcing everything into frame-local blocks.

Important distinction:

```text
immutable object
    vs
mutable-by-transition instance state
```

An object may remain immutable forever.

An instance may change:

```text
position
transform
visibility
clip
palette binding
residual binding
z-order
```

through transitions.

# 17. INITIAL REPRESENTATION FAMILIES

Do NOT begin with twenty codec modes.

The initial procedural state needs only enough mechanisms to test persistent state.

Implement sequentially.

## RAW

```text
RAW_REF
```

Universal escape hatch.

## FILL

```text
FILL
```

## EXACT_OBJECT_REF

Reuse immutable exact data.

## UNCHANGED

Persistent instance/state remains unchanged across transition interval.

This is conceptually important.

It makes "nothing happened" a first-class cheap temporal representation.

## SPARSE_PATCH

Patch only changed positions.

## COPY_RECT

Explicitly copy a 2D region from a permitted previous/materialized object.

## INTEGER_TRANSLATION

Persistent object/region translated by integer coordinates.

## RANS_RESIDUAL

Ordinary entropy-coded residual floor.

These are sufficient for the first serious procedural experiment.

# 18. UNCHANGED IS NOT A ZERO-BYTE MAGIC CLAIM

Persistent unchanged state may reduce repeated representation, but accounting still includes:

* checkpoint state;
* object declarations;
* transition timing;
* indexes;
* integrity;
* stream metadata.

The correct claim is not:

> unchanged frames cost zero.

The correct question is:

> What is the amortized representation cost of maintaining unchanged persistent state?

Measure it.

# 20. PARAMETRIC DYNAMICS

One of the key procedural goals is to replace repeated parameter updates with compact deterministic trajectories where this is actually cheaper.

Examples:

$$
x(t)=x_0+vt
$$

or:

$$
x(t)=x_0+vt+\frac12at^2.
$$

Later support bounded fixed-point trajectories such as:

```text
Constant
Linear
Acceleration
PiecewiseLinear
BoundedSpline
```

Do not use floating point normatively.

Every trajectory must define exact evaluation semantics.

A trajectory only wins if:

```text
trajectory descriptor
+ corrections/residual
```

is cheaper than ordinary state updates.

# 24. DSFB SEMANTICS

A useful interpretation:

```text
φ = current explanatory quality of procedural hypothesis
ω = gradual drift of that explanatory quality
α = rapid structural regime change
```

Example:

```text
region follows translation for 500 intervals
residual remains tiny

then object deforms
residual rises sharply
```

High slew may trigger:

```text
broaden candidate search
test affine
test split regions
test sparse mutation
test rebase
test transform fallback
```

After another family stabilizes, search narrows again.

This is a major research mechanism.

# 26. DSFB ZERO AUTHORITY

DSFB may:

* rank procedural hypotheses;
* change search order;
* change candidate budget;
* select expensive families to test;
* recommend region rebase;
* adjust motion/affine search depth;
* schedule background optimization.

DSFB may NOT:

* alter samples;
* alter normative state semantics;
* make invalid reconstruction acceptable;
* suppress RAW permanently;
* select an unvalidated candidate;
* override exact final cost among evaluated candidates;
* be required to decode.

# 27. DETERMINISTIC SENTINELS

Prevent search starvation.

Always test:



# 77. FINAL ENGINEERING PRINCIPLE

Do not let VOLE regress into:

> A conventional video codec with extra prediction modes.

And do not let it expand into:

> An unbounded scene scripting platform.

VOLE should remain:

> **A finite, deterministic, auditable procedural video state machine in which persistent mathematical/configurational structure is stored and transported directly, residual information closes the gap to the target observation, and raster samples are materialized only as required.**

Every persistent bit must be accounted for.

Every procedural operation must be bounded.

Every lossless candidate must reproduce the target exactly.

Every search optimization must remain subordinate to the materializer.

Every claim must survive an empirical court.

Build the procedural video system first.

Then let the evidence tell us how much of video can actually become math.

```

This version changes the implementation order in the important way: **`ProceduralState → Checkpoint → Transition → Materialize` now exists before motion estimation, rANS sophistication, transforms, or DSFB.** That matches the improved paper rather than treating procedural representation as just another descriptor family.
```
